# 언스크류 (UNCREW)

> 풀수록, 더 깊이 얽힌다.

타인의 비밀을 알아야 살아남지만, 알고 있다는 사실을 들키면 죽는 회귀 생존 미스터리입니다. 이 폴더에는 「언스크류 에이전트 AI 프로토타입 구현 명세 v0.1」의 **P0 범위, 첫 사건 「어제의 전달 목록」(D-30)** 을 끝까지 플레이할 수 있는 웹 프로토타입이 들어 있습니다.

타이틀 → 사망 프롤로그(십 년의 충성 → 회장실 청소부라 불린 해결사의 방식 → 첫 번째 삶의 마지막 30일 → 배신과 죽음의 밤) → 회귀 직후의 혼란 → 이름 떠올리기(입력) → 능력 발견과 목표 → 서해린과의 첫 대화 → 연습 해체(튜토리얼) → 회장실 인사 → 멈춘 시간(기억 조사 허브) → 스크류 퍼즐 → 단서·아이템 획득 → 전달 목록 요청 → 회장 대면 3회 → 결과(4종)까지 이어집니다.

## 바로 플레이하기

**https://kenihy.github.io/ScrewPuzzle/**

휴대폰이나 PC 브라우저에서 위 주소를 열면 언스크류가 바로 실행됩니다. 로그인이나 설치는 필요 없습니다. 이전 프로토타입(하트볼트)은 `https://kenihy.github.io/ScrewPuzzle/prototype/`에 그대로 있습니다.

휴대폰에서는 홈 화면에 추가하면 주소창 없이 앱처럼 전체 화면으로 실행됩니다.

- iPhone(Safari): 공유 버튼 → **홈 화면에 추가**
- Android(Chrome): 오른쪽 위 메뉴(⋮) → **홈 화면에 추가** 또는 **앱 설치**

## 내 컴퓨터에서 실행

`uncrew/index.html` 파일을 브라우저로 바로 열면(더블클릭) 실행됩니다. 웹 서버나 설치가 필요 없습니다. 같은 와이파이의 휴대폰에서 열고 싶을 때는 간단한 웹 서버를 씁니다.

```bash
cd uncrew && python3 -m http.server 8000
```

그다음 `http://<PC의 IP>:8000`으로 접속합니다. 네트워크가 없어도 플레이할 수 있고, 이때 웹 폰트 대신 시스템 글꼴로 표시됩니다.

## 코드를 고친 뒤

화면은 `src/`의 모듈을 하나로 묶은 `uncrew.bundle.js`로 실행됩니다. 이렇게 해야 파일을 직접 열어도 동작합니다. `src/`를 고친 뒤에는 번들을 다시 만드세요. 번들이 원본과 다르면 `npm test`가 실패해 알려 줍니다.

```bash
cd uncrew && node tools/build.mjs
```

## 조작 방법

| 화면 | 조작 |
|---|---|
| 대화 | 대사 상자를 누르면 전체 대사가 바로 표시됩니다. **다음**은 대사가 모두 표시된 뒤에만 눌립니다. **건너뛰기**는 장면의 마지막 줄까지만 넘기며 선택지를 대신 고르지 않습니다. |
| 대화(키보드) | Space: 전체 보기 · Enter 또는 →: 다음 · Esc: 창 닫기·선택 취소 |
| 선택지 | 잠긴 선택지에는 필요한 조건이 표시됩니다. 수치 변화는 고른 뒤에 상단 띠로 보여 줍니다. |
| 기억 돋보기 · 대화 리허설 | 선택지 위 아이템 줄에서 사용합니다. 리허설은 버튼을 누른 뒤 미리 볼 선택지를 고릅니다. |
| 멈춘 시간(허브) | 주제를 누르면 난이도 창이 열립니다. 집중력은 **조사 시작**을 누를 때만 줄어듭니다. |
| 퍼즐 | 나사를 눌러 집고(금색 실선 고리), 점선 고리와 중심점이 표시된 빈 구멍을 눌러 옮깁니다. 같은 나사를 다시 누르거나 Esc를 누르면 선택이 취소됩니다. 판을 지지하는 나사가 모두 빠지면 판이 떨어지고, 아래에 가려져 있던 나사와 구멍이 드러납니다. |
| 퍼즐 도구 | 되감기 · 임시 나사함 · 처음부터(집중력 추가 소모 없음) · 포기(환급 없음) |
| 노트 | 상단 문서 아이콘. **상황**(이번 사건 목표·진행 방법, 이번 삶의 목표, 지금 처지와 해결 방향, 첫 번째 삶의 기록) · 기억 단서 · 확보 증거 · 인물 탭. PC처럼 넓은 화면(가로 980px 이상)에서는 오른쪽에 항상 표시됩니다. |
| 대사 기록 | 대사 아래 **기록**, 선택지 위 **이전 대사 보기**, 허브·결과 화면·메뉴에서 엽니다. 이번 시도에서 지금 줄까지 나온 대사와 내가 고른 대답, 그때의 의심도·신뢰도 변화를 순서대로 보여 줍니다. 닫으면 보던 화면으로 돌아갑니다. |
| 용어 안내 | 선택지 위·보상 화면·노트·허브·메뉴의 **용어 안내**. 기억 단서, 확보 증거, 표면·중층·심층, 단서 카드 읽는 법, 집중력, 의심도·신뢰도, 아이템을 설명합니다. |
| 메뉴 | 상단 왼쪽 ≡. 노트 · 대사 기록 · 용어 안내 · 설정 · 사건 처음부터 다시 · 타이틀로 |

## 기억 단서가 작동하는 방식

퍼즐을 풀면 얻는 **기억 단서** 카드에는 세 가지 정보가 붙습니다.

- **깊이**: 표면(상대가 내세우는 명분·이미 아는 사실) · 중층(감추는 행동과 구체적 기억) · 심층(그 행동을 만든 욕망·두려움, 숨은 전제). 쉬움은 표면, 보통은 중층까지, 어려움은 심층까지 엽니다.
- **판단 힌트**: 이 단서가 대화에서 무엇을 뜻하는지 정리한 해설입니다. 예를 들어 ‘회장은 만남을 이미 안다’는 단서는 “만나지 않았다고 하면 거짓말이 드러난다”는 뜻입니다.
- **작동**: 게임 규칙상 실제로 연결된 곳입니다. 콘텐츠 데이터의 선택지 조건에서 자동으로 계산합니다.
  - 선택지를 엶: 그 단서가 조건인 대답이 어느 장면에 있는지, 조건을 지금 얼마나 갖췄는지(✓·✗)
  - 모순 확인: 그 단서와 어긋나는 대답이 있는 장면 (기억 돋보기로 표시 가능)
  - 관련 표시: 관련 선택지 옆에 ‘관련 단서 보유’가 뜨는 장면

선택지에서도 같은 조건표를 보여 줍니다. 잠긴 대답에는 **필요** 조건이, 단서로 열린 대답에는 **근거**가 ✓·✗로 표시됩니다. 아직 보지 못한 단서는 이름(인물·주제·깊이)만 보이고 내용은 드러나지 않습니다.
| 테스트 패널 | 설정에서 켜거나 ` 키로 전환합니다. 기본은 숨김입니다. |

진행은 상태가 바뀔 때마다 자동 저장되며, 타이틀의 **이어하기**로 돌아올 수 있습니다.

## 주인공 이름

주인공은 프롤로그와 회귀 직후에는 **나**로만 표시됩니다. 회귀한 직후 어지러운 상태에서 자기 이름부터 떠올리는 장면이 나오고, 이때 이름을 입력합니다. 이후 대사·속마음 화자·단서 문장·인물 노트에 입력한 이름이 들어가며, 조사(아/야, 과/와, 이/가 등)는 받침에 맞춰 자동으로 바뀝니다. 예를 들어 이름이 ‘민호’면 회장은 “민호야”, 직원들은 “강 실장님”이라고 부릅니다.

이름 규칙은 현재 등장인물 구성(모두 성 1자 + 이름 2자, 회장 일가는 차씨)과 대사 형태에 맞춰 정했습니다.

| 규칙 | 이유 |
|---|---|
| 한글 완성형 글자만 (영문·숫자·공백·기호·자모 단독 불가) | 대사와 조사 처리가 한국어 이름을 전제로 합니다. |
| 성 1자, 또는 복성 2자(남궁·황보·제갈·선우·독고·사공·서문·동방) | “○ 실장님” 호칭이 자연스럽게 읽혀야 합니다. 목록에 없는 2자 성은 오타로 봅니다. |
| 이름 2자 | 다른 인물과 같은 길이이고, “○○아/야”로 부를 때 어색하지 않습니다. |
| 성 ‘차’ 불가 | 회장 일가(차태건·차유라·차도혁)와 혈연으로 읽힙니다. |
| 다른 등장인물의 이름(태건·해린·유라·서진·리아·도혁·무진) 불가 | 대사에서 누구를 부르는지 헷갈립니다. |
| 호칭·직함으로 읽히는 이름(회장·실장·비서 등), 비속어 불가 | 대사가 깨지거나 부적절하게 읽힙니다. |

입력하지 않고 **한도윤 그대로**를 고르면 기본 이름으로 진행합니다. 사건 재도전은 이름을 유지하고, 새 게임에서는 다시 묻되 지난 이름을 미리 채워 둡니다. 이름은 이 브라우저의 저장 데이터에만 남고 로그에는 기록하지 않습니다.

## 구성

| 경로 | 내용 |
|---|---|
| `index.html`, `styles.css` | 화면 틀과 스타일 (모바일 세로 기준, PC는 중앙 세로 패널 + 오른쪽 노트) |
| `uncrew.bundle.js` | 실행용 단일 스크립트. `src/`에서 자동 생성되며 직접 고치지 않습니다. |
| `manifest.webmanifest`, `icons/` | 홈 화면 추가용 앱 정보와 아이콘 |
| `src/main.js` | 진입점. 콘텐츠를 검증한 뒤 게임과 UI를 연결합니다. 검증 오류가 있으면 시작하지 않고 목록을 보여 줍니다. |
| `src/core/puzzleEngine.js` | 퍼즐 엔진. 이동 가능성 · 판 제거 · undo · 임시 나사함 · 클리어/실패 판정 (순수 함수) |
| `src/core/game.js` | 게임 상태와 원자적 변경, 대화 효과 적용, 보상 지급과 중복 방지, 결과 판정 |
| `src/core/transcript.js` | 대사 기록. 저장된 진행(지나온 장면·고른 대답)만으로 지금까지 나온 대사를 다시 만듭니다. |
| `src/core/clueInfo.js` | 단서·증거가 연결된 선택지(조건·모순·관련 표시)를 찾고 ✓·✗ 조건표를 만듭니다. |
| `src/data/guide.js` | 용어 안내 문구 |
| `src/core/names.js` | 주인공 이름 규칙, 받침에 맞춘 조사 처리, 대본 이름 자리 표시 치환 |
| `src/core/conditions.js` | 구조화된 all/any 조건 평가기 (문자열 eval 없음) |
| `src/core/save.js` | 저장·복원·스키마 검증, 깨진 저장 격리, 로컬 이벤트 로그 |
| `src/core/validate.js` | 콘텐츠 로딩 검증 (누락 · 미등록 ID · 중복 ID · 판 영역과 구멍 목록 불일치) |
| `src/core/solver.js` | 너비 우선 탐색 풀이기. 튜토리얼 힌트와 개발용 검증에만 사용 |
| `src/data/puzzles.js` | 명세 부록 A의 검증된 퍼즐 3종 원본 + 튜토리얼 보드(별도 ID) |
| `src/data/case01.js` | 첫 사건 대본 · 선택지 · 단서 · 증거 · 주제 · 결과 |
| `src/data/config.js` | 초기 수치 · 난이도 · 아이템 · 의심도 구간 |
| `src/data/expansion.js` | 전체판 확장용 세계관 데이터 (P0 실행 코드에서는 불러오지 않음) |
| `src/ui/` | UI 컨트롤러, SVG 보드 렌더러, 대체 실루엣 일러스트, 합성 효과음 |
| `tests/` | Node 내장 테스트 러너로 실행하는 자동 검증 |
| `tools/build.mjs` | `src/`를 `uncrew.bundle.js`로 묶는 생성기 (외부 패키지 없음) |
| `tools/e2e-playthrough.mjs` | 실제 브라우저에서 클릭으로 끝까지 플레이하는 자동 검증 (선택 사항) |
| `tools/make-icons.mjs` | 타이틀 엠블럼으로 홈 화면 아이콘 생성 (선택 사항) |

게임 규칙(core)과 화면(ui)을 분리했으므로, Unity로 옮길 때는 `src/data`의 데이터와 `src/core`의 규칙을 그대로 C#으로 옮기면 됩니다.

- 이름 규칙(허용·거부 사례), 조사 처리, 이름 입력 흐름, 재도전 시 이름 유지, 이전 저장 형식 변환, 이름 없는 깨진 저장 처리

## 기본값으로 정한 사항

명세에 지정되지 않은 저위험 사항은 아래처럼 정했습니다. 제목, 핵심 루프, 기본 승패 조건, 수치 표는 명세 그대로입니다.

1. **엔진과 위치**: 저장소에 이미 같은 방식(브라우저에서 바로 여는 HTML/JS)의 웹 프로토타입(하트볼트)이 있어 그 관례를 따랐습니다. 하트볼트 코드는 건드리지 않고 `uncrew/` 폴더에 새로 만들었으며, 저장소 첫 화면(`index.html`)만 언스크류로 이동하도록 바꿨습니다.
2. **도입 장면 노드**: 명세의 RETURN 뒤에 이름 입력 화면(`NAME_ENTRY`)과 능력 발견·목표 장면(`AWAKEN`)을 넣었습니다. 이름을 떠올리기 전이므로 프롤로그의 보안실장 대사는 명세의 “한 실장님” 대신 “실장님”으로 부릅니다. 회장이 살해의 최종 결정권자라는 사실은 여전히 확정하지 않습니다.
3. **인사 장면 노드**: 명세 14.2의 "허브는 회장실 입장 직후 인사 장면에서 열린다"를 구현하려고 TUTORIAL과 MEMORY_HUB 사이에 짧은 장면 `OFFICE_ENTER`를 넣었습니다. 선택지나 수치 변화는 없습니다.
4. **재도전 체크포인트**: 서해린의 첫 대화(HAERIN_OPEN)부터 다시 시작하며 프롤로그는 생략합니다. 튜토리얼은 다시 나오지만 바로 건너뛸 수 있습니다.
5. **실패 상태의 되감기**: 이동 한도에 도달한 뒤에도 되감기 도구가 있으면 직전 이동을 되돌려 계속할 수 있습니다. 클리어 후에는 쓸 수 없습니다.
6. **판 라벨과 분위기 문구**: 주제마다 판 이름과 판이 떨어질 때의 문구를 붙였습니다. 낮은 난이도에서 깊은 단서가 새지 않도록 문구에는 단서 내용을 넣지 않았습니다.
7. **의심도 구간 연출**: 관찰 대상(40) · 제거 검토(70)에 처음 들어설 때 한 번씩 짧은 장면 반응을 덧붙입니다. 수치나 선택 규칙은 바꾸지 않습니다. 70 이상인 회장실 장면에는 문 밖 보안실장 실루엣이 계속 보입니다.
8. **제거 연출**: 의심도 100에 도달하면 선택지 고유 반응 대신 공통 제거 장면(침묵 → 보안실장 호출 → 암전)을 보여 준 뒤 결과로 갑니다.
9. **리허설 방향**: 선택지 효과의 변화량 부호로 판단합니다(0~100 보정 전). 예를 들어 의심도 0에서 −5인 선택지는 "하락"으로 표시합니다.
10. **돋보기 대상 순서**: 모순 대상이 여럿이면 선택지 순서상 첫 번째를 표시하고, 다시 쓰면 다음 대상을 표시합니다.
11. **오클릭 방지**: 대사가 모두 표시된 직후 0.18초, 화면이 바뀐 직후 0.32초 동안은 입력을 무시합니다.
12. **난이도 창 기본 선택**: 남은 집중력으로 시작할 수 있는 가장 낮은 난이도를 미리 선택합니다.
13. **튜토리얼 힌트**: 풀이기로 다음 한 수를 계산해 강조만 합니다. 정답을 자동으로 실행하지 않습니다.
14. **저장 방식**: `localStorage` 키 `uncrew.save.v1` 하나에 RunState · PuzzleState · MetaState를 함께 써서 보상과 보드 상태가 따로 저장되지 않게 했습니다. 깨진 저장은 `uncrew.save.corrupt.<시각>`으로 옮겨 두고 새 게임을 안내합니다. 로컬 로그는 `uncrew.log.v1`에 최근 400건만 남기며 외부로 보내지 않습니다. 저장 형식은 v2(주인공 이름 추가)이며, 이전 v1 저장은 기본 이름(한도윤)으로 자동 변환해 이어 할 수 있습니다.
15. **좁은 화면의 보드**: 가로 400px 이하에서는 보드를 화면 폭 전체로 넓혀 인접 구멍(80 단위) 사이 간격을 44px 이상으로 맞췄습니다.
16. **그림과 소리**: 인물은 SVG 실루엣으로, 효과음은 Web Audio 합성음으로 대체했습니다. 외부 이미지·음원 파일이 없습니다. 대화 장면에는 아주 작은 저음 배경음이 있고 큰 의심 증가 때 잠시 낮아집니다.
17. **결과 화면의 플레이 시간**: 사건 시작부터 결과까지 걸린 시간을 표시합니다. 실제 플레이 시간 측정에 쓸 수 있습니다.
18. **개발용 핸들**: 브라우저 콘솔에서 `__uncrew.game`으로 상태를 볼 수 있습니다. 테스트 패널의 "해법 재생"은 개발용이며 기본 화면에는 없습니다.
