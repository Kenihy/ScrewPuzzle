# 나사 너머 — 기획 및 Unity 이식 문서 (프로토타입 v0.1)

가제 **나사 너머**는 스크류 퍼즐을 풀어 캐릭터가 감추고 있던 속마음과 모습을 드러내는 퍼즐 게임입니다. 퍼즐 판 뒤에 캐릭터 일러스트가 깔려 있고, 판을 떼어 낼 때마다 그 자리가 선명해집니다. 스테이지를 깨면 캐릭터의 설정 조각이 열리고, 마지막 스테이지에서 전체 일러스트와 '이면'이 공개됩니다.

이 문서는 웹 프로토타입(`prototype/`)에서 확정한 규칙과 콘텐츠 구조를 정리한 것입니다. Unity 개발자는 이 문서와 `prototype/rules.js`, `tools/data/levels.json`을 기준으로 본 개발을 진행하면 됩니다.

- 목표 플랫폼: Steam (Unity)
- 프로토타입: HTML5 Canvas, 휴대폰 세로 화면 기준. 규칙·콘텐츠 검증용이며 최종 UI 레이아웃은 아닙니다.

---

## 1. 핵심 루프

1. 캐릭터(챕터)를 고르고 스테이지에 들어갑니다.
2. 나사를 눌러 들어 올리고, 비어 있는 구멍을 눌러 옮깁니다.
3. 나사가 하나도 남지 않은 판은 떨어지고, 판이 있던 자리의 일러스트가 선명해집니다.
4. 모든 판을 떨어뜨리면 일러스트 전체가 드러나고 **마음 조각** 한 장을 얻습니다.
5. 다섯 번째 스테이지를 깨면 전체 일러스트(이면)가 공개되고, 다음 캐릭터가 열립니다.

판 뒤 일러스트는 퍼즐 중에는 흐리고 어둡게 보이다가, 판이 떨어진 자리만 선명해집니다. 플레이 도중에도 보상을 계속 느끼게 하려는 장치입니다.

## 2. 콘텐츠 구조

### 챕터 = 캐릭터

| 단위 | 내용 |
|---|---|
| 챕터 | 캐릭터 1명. 스테이지 5개, 마음 조각 5장, 비밀 메모 1장, 전체 일러스트 1장 |
| 스테이지 | 퍼즐 1판. 뒤에 깔리는 일러스트 영역(크롭)이 스테이지마다 다릅니다 |
| 마음 조각 | 스테이지를 처음 깨면 열리는 설정 카드 |
| 비밀 메모 | 챕터의 별 15개(모든 스테이지 3별)를 모으면 열리는 보너스 |

일러스트 한 장으로 다섯 스테이지를 구성합니다. 스테이지가 진행될수록 확대 배율을 줄여(2.4배 → 1배), 처음에는 장소나 소품만 보이다가 마지막에 전체 모습이 드러나도록 했습니다. 캐릭터당 일러스트 1장만으로 챕터를 만들 수 있어 제작비 부담이 적습니다. 본 개발에서는 스테이지 4~5용 일러스트를 따로 그려 보상감을 키우는 방안도 검토할 만합니다.

### 마음 조각 5단계

| 스테이지 | 카드 종류 | 역할 |
|---|---|---|
| 1 | 프로필 | 이름, 나이, 하는 일. 남들이 아는 정보 |
| 2 | 겉으로 하는 말 | 겉으로 보이는 태도와 대사 |
| 3 | 속마음 | 겉모습과 어긋나는 속마음이 처음 드러남 |
| 4 | 숨겨진 기억 | 그렇게 된 이유가 된 과거 |
| 5 | 이면 | 감춰 왔던 진짜 마음. 전체 일러스트와 함께 공개 |

### 해금 조건

- 제나(튜토리얼 챕터)는 처음부터 열려 있습니다.
- 스테이지는 앞 스테이지를 깨면 열립니다.
- 제나 챕터를 모두 깨면 엘라와 미오 챕터가 동시에 열리고, 플레이어가 순서를 고릅니다.

### 캐릭터 (프로토타입 수록분)

| 캐릭터 | 겉모습 | 이면 | 새 장치 | 판 재질 |
|---|---|---|---|---|
| 제나 · 거리 댄서 | 무심하고 날 선 태도 | 무대 공포를 숨기며, 매번 맨 앞에 서던 한 명의 관객을 기다림 | 없음 (기본 규칙 익히기) | 공사장 표지, 아스팔트, 콘크리트 |
| 엘라 · 패션 인플루언서 | 화려하고 여유로운 인기인 | 매일 밤 빈 극장에 혼자 앉아 누군가를 기다림 | 얼음 나사 | 극장 벨벳, 금색 장식 |
| 미오 · 도서관 사서 | 규칙에 엄격한 철벽 사서 | 책 속 쪽지로 3년째 이름 모를 사람과 편지를 주고받음 | 자물쇠 나사 + 열쇠 판 | 가죽 책 표지, 금박 |

장치는 캐릭터 성격과 연결했습니다. 차가운 미소의 엘라에게는 얼음, 비밀이 많은 미오에게는 자물쇠를 붙였습니다. 새 캐릭터를 추가할 때도 같은 원칙(성격 → 장치 → 판 재질)을 따르면 됩니다.

캐릭터 이름과 설정 문구는 모두 가안입니다. 텍스트는 `prototype/content.js`에 모여 있습니다.

## 3. 퍼즐 규칙 (구현 기준)

규칙 구현의 원본은 `prototype/rules.js`입니다. 렌더링과 분리된 순수 로직이므로 C#으로 거의 그대로 옮길 수 있습니다.

### 좌표

- 보드는 300 × 400 단위이며, 일러스트와 같은 3:4 비율입니다.
- 판과 구멍은 5열 × 7행 격자점 위에 놓입니다. 격자점 (i, j)의 좌표는 `x = 40 + 55i`, `y = 35 + 55j`입니다.
- 보드 위쪽에 **보관 구멍**이 기본 3개(최대 6개) 있습니다.

### 판(plank)

- `bar`: 두 격자점을 잇는 막대. 가로·세로·45° 대각선만 허용합니다. 반폭은 19입니다.
- `panel`: 두 격자점을 대각 꼭짓점으로 하는 사각 판. 격자점 바깥으로 22만큼 나옵니다.
- 판은 자신이 지나는 격자점을 **덮습니다**. 막대는 선분 위의 격자점, 판넬은 사각형 안의 모든 격자점을 덮습니다.
- 판마다 구멍 위치(`holes`)가 정해져 있습니다. 레벨 데이터의 판 순서가 곧 쌓인 순서(아래 → 위)입니다.

### 구멍과 나사

- **보드 구멍**은 판 구멍 위치의 합집합입니다. 판이 떨어져도 보드 구멍은 남습니다.
- 한 구멍 위치에서 '구멍 뚫린 판'은 항상 아래쪽부터 연속으로 쌓입니다. 구멍 뚫린 판 아래에 막힌 판이 오지 않도록 레벨을 만들어야 합니다(`validate()`가 검사).
- **열린 구멍**: 그 위치를 덮는 살아 있는 판이 모두 같은 자리에 구멍을 가진 경우. 보관 구멍은 항상 열려 있습니다.
- 나사는 구멍 위치에 박혀 있고, 그 위치에 구멍이 있는 판을 모두 고정합니다.
- 나사가 열린 구멍에 있을 때만 집을 수 있습니다. 위에 막힌 판이 덮고 있으면 **가려진 나사**입니다.

### 이동

1. 집을 수 있는 나사를 누르면 들어 올립니다.
2. 비어 있고 열린 구멍을 누르면 그 구멍으로 옮깁니다. 이동 수가 1 늘어납니다.
3. 옮긴 뒤, 자신의 구멍에 나사가 하나도 없는 판은 즉시 떨어집니다.
4. 모든 판이 떨어지면 클리어입니다.

나사를 다른 판의 빈 구멍에 꽂으면 그 판을 다시 고정합니다. 보관 구멍이 부족할 때 쓰는 핵심 전략입니다.

### 장치(기믹)

| 장치 | 규칙 |
|---|---|
| 얼음 나사 | `ice: N`. 전체 이동 수가 N이 될 때까지 집을 수 없습니다. 화면에는 남은 횟수를 표시합니다 |
| 자물쇠 나사 | `lock: true`. 열쇠 판(`key: true`)이 떨어지기 전에는 집을 수 없습니다 |

### 도구

| 도구 | 효과 | 기본 개수 |
|---|---|---|
| 망치 | 판 하나를 즉시 부숩니다. 이동 수는 늘지 않습니다 | 3 |
| 구멍 추가 | 보관 구멍을 1개 늘립니다 (최대 6개) | 3 |
| 힌트 | 풀이기가 찾은 다음 수를 표시합니다 | 3 |

- 스테이지를 처음 깨면 도구를 1개씩 돌아가며 지급합니다(망치 → 구멍 추가 → 힌트).
- 도구를 한 번이라도 쓰면 그 판의 별은 최대 2개입니다.

### 별

- 레벨마다 최소 이동 수(`par`)를 A* 탐색으로 미리 계산해 둡니다.
- 3별: 이동 수 ≤ par + 1, 도구 미사용
- 2별: 이동 수 ≤ ⌈par × 1.5⌉ + 1
- 1별: 그 밖의 클리어

### 막힘 처리

- 옮길 수 있는 나사가 없으면 즉시 안내 시트를 띄웁니다.
- 겉보기엔 움직일 수 있어도 이미 풀 수 없는 배치가 되면, 풀이기(탐색 한도 12,000)가 이를 증명했을 때 안내합니다.
- 안내 시트에서 망치, 구멍 추가, 다시 하기를 고를 수 있습니다.

## 4. 레벨 데이터

`tools/data/levels.json`이 원본입니다. Unity에서는 이 파일을 `TextAsset`으로 읽거나, 에디터 스크립트로 `ScriptableObject`로 변환해 쓰면 됩니다. 아래는 형식을 보여 주는 예시이며, 실제 값은 파일에서 확인하세요.

```json
{
  "id": "mio-3", "character": "mio", "stage": 3,
  "tray": 3, "par": 18,
  "planks": [
    { "kind": "bar", "a": [0, 1], "b": [0, 5], "holes": [[0, 1], [0, 5]], "color": 3 },
    { "kind": "panel", "a": [1, 0], "b": [3, 2], "holes": [[1, 0], [3, 2]], "color": 1, "key": true }
  ],
  "screws": [ { "at": [0, 1] }, { "at": [1, 0], "lock": true }, { "at": [3, 2], "ice": 4 } ],
  "meta": { "success": 0.39, "cover": 0.62, "target": 0.5 }
}
```

- 좌표는 모두 격자 인덱스 `[i, j]`입니다.
- `color`는 캐릭터별 판 색상표(6색)의 인덱스입니다.
- `meta.success`는 무작위 플레이어 300판의 성공률이고, `meta.cover`는 판이 보드를 덮는 비율입니다.

### 레벨 생성기

```bash
node tools/levelgen.mjs
```

```bash
ONLY=ella-3,mio-5 node tools/levelgen.mjs
```

첫 번째 명령은 15개 레벨을 모두 다시 만듭니다(약 10분). 두 번째 명령은 지정한 레벨만 다시 만들고 나머지는 유지합니다.

생성 과정은 다음과 같습니다.

1. 시드 기반으로 판을 무작위 배치합니다. 75% 확률로 좌우 대칭 쌍을 만들어 보기 좋게 정돈합니다.
2. 풀이기로 도구 없이 풀 수 있는지 확인합니다.
3. 무작위 플레이 성공률을 스테이지 목표치(1스테이지 85~97% → 5스테이지 25~30%)와 비교해 가장 가까운 배치를 고릅니다.
4. 고른 배치의 최소 이동 수를 A*로 계산해 `par`로 저장합니다.

튜토리얼(제나 1스테이지)은 생성기 안의 `FIXED`에 직접 설계해 두었습니다. 가려진 나사와 판이 떨어진 자리의 빈 구멍을 6번 이동 안에 경험하도록 구성했습니다.

## 5. 화면 구성

| 화면 | 내용 |
|---|---|
| 홈 | 캐릭터 카드 목록. 잠긴 캐릭터는 흐린 실루엣과 해금 조건 표시 |
| 챕터 | 캐릭터 정보(겉모습), 장치 안내, 스테이지 5개, 마음 조각 목록, 비밀 메모, 전체 일러스트 보기 |
| 퍼즐 | 이동 수와 3별 목표, 보관 구멍, 보드, 도구 3종, 다시 하기 |
| 결과 | 별, 마음 조각 카드, 첫 클리어 보상, 다음 이야기 |
| 감상 | 챕터를 마치면 전체 일러스트를 크게 볼 수 있음 |
| 설정 | 효과음, 모든 스테이지 열기(검토용), 진행 초기화 |

튜토리얼에서는 안내 문구가 단계별로 바뀝니다(나사 들기 → 옮기기 → 판 떨어뜨리기 → 일러스트가 드러남). 새 장치가 처음 나오는 스테이지에서는 장치 설명을 한 번 보여 줍니다.

## 6. 일러스트 연출 구현

프로토타입은 일러스트를 레이어 네 장으로 나눠 그립니다. Unity에서는 셰이더 한 개와 마스크용 RenderTexture로 같은 효과를 낼 수 있습니다.

1. **선명 레이어**: 스테이지 크롭 영역의 원본 이미지
2. **흐림 레이어**: 선명 레이어를 축소·확대해 흐리게 만들고, 채도를 낮추고 어둡게 덮은 이미지
3. **마스크**: 떨어진 판의 모양을 부드러운 가장자리로 칠한 알파 이미지. 판이 떨어질 때 0.55초 동안 알파가 차오릅니다
4. **드러남 레이어**: 선명 레이어 × 마스크

화면에는 흐림 → 드러남 → (클리어 시) 선명 레이어를 1.1초간 페이드 인하는 순서로 겹칩니다.

## 7. Unity 이식 가이드

### 권장 구조

| 구성 요소 | 역할 | 프로토타입 대응 |
|---|---|---|
| `PuzzleRules` (순수 C#) | 모델 생성, 이동, 낙하 판정, 풀이기, A* | `rules.js` 전체 |
| `LevelData` / `LevelDatabase` | `levels.json` 가져오기 | `levels.js` |
| `CharacterData` (ScriptableObject) | 이름, 일러스트, 스테이지 크롭, 마음 조각, 판 색상 | `content.js` |
| `BoardView` | 판·나사·구멍 배치, 쌓임 순서(sorting order) | `draw()` |
| `RevealController` | 흐림·마스크 셰이더, 판 낙하 시 마스크 갱신 | `buildLayers()`, `recomposeReveal()` |
| `PuzzleInput` | 마우스·터치 입력, 가장 가까운 나사·구멍 판정(반경 24) | `onTap()` |
| `ProgressService` | 별, 도구, 해금 상태 저장. Steam Cloud 연동 | `save` 객체 |

`PuzzleRules`를 렌더링과 분리해 두면 단위 테스트와 레벨 검증 도구를 엔진 밖에서도 그대로 쓸 수 있습니다.

### Steam 출시를 위해 바뀌어야 할 점

- **가로 화면 레이아웃**: 프로토타입은 휴대폰 세로 화면용입니다. PC(16:9)와 Steam Deck(16:10)에서는 보드를 가운데나 왼쪽에 두고, 오른쪽에 캐릭터 정보와 마음 조각 패널을 두는 구성이 자연스럽습니다.
- **마우스 입력**: 마우스를 올린 나사와 구멍을 강조하면 탭 입력보다 조작이 편해집니다. 오른쪽 클릭으로 선택 취소를 넣는 것도 좋습니다.
- **Steam 기능**: 챕터 완료와 별 15개 달성을 도전 과제로, 진행 상황은 Steam Cloud로 저장합니다.
- **연령 등급**: 일러스트의 노출 수준에 따라 Steam 콘텐츠 설문에서 선정적 콘텐츠 항목을 신고해야 할 수 있습니다. 해금 보상을 노출이 아닌 이야기 중심으로 두면 등급 대응이 쉬워집니다.

## 8. 프로토타입의 한계와 다음 단계

- **물리 없음**: 판은 나사가 모두 빠졌을 때만 떨어집니다. 나사 하나에 매달려 회전하는 연출은 없습니다. Unity에서 HingeJoint2D로 넣을 수 있지만, 회전한 판이 다른 구멍을 가리면 레벨 검증이 어려워지므로 연출용으로만 쓰는 편을 권합니다.
- **난이도 추정**: 무작위 플레이 성공률은 사람보다 서툰 플레이어 기준이라 실제 체감 난이도와 다를 수 있습니다. 플레이 테스트로 보정해야 합니다.
- **시간 제한 없음**: 속마음을 천천히 읽는 분위기에 맞춰 뺐습니다. 도전 모드로 따로 추가할 수 있습니다.
- **효과음**: 브라우저에서 즉석 합성한 임시 소리입니다.
- **검증할 것**: 스테이지 1개당 플레이 시간, 마음 조각을 읽는 비율, 도구 사용 빈도, 막힘 안내가 뜨는 빈도.
